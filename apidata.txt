# USERS MODULE

# IMPORTANT: ACCESS-BASED FILTERING
# All listing APIs now implement access-based filtering using the 'canViewAll' permission:
# - If userAccess.module.canViewAll = true: Returns ALL records
# - If userAccess.module.canViewAll = false: Returns only records where createdBy = currentUser.userId
# 
# The JWT token is automatically decrypted and user information is available in req.headers["currentUser"]

# IMPORTANT NOTES FOR COLLECTION FILTERING:
# 1. Filter Parameter Names: Use the "filterName" from your collection configuration as query parameters
# 2. Field Matching: The system searches in the "fieldName" specified in the filter configuration
# 3. Case Insensitive: Both field names and values are matched case-insensitively
# 4. Partial Matching: Search terms can be partial matches (e.g., "test" matches "Testing")
# 5. Multiple Filters: All provided filters must match (AND operation)
# 6. Mandatory Filters: If a filter has "isMandatory: true", it must be provided in the query
# 7. No Filters: If no query parameters are provided, returns all contents for the collection's content type

# FILTER CONFIGURATION EXAMPLE:
# If your collection has this filter:
# {
#   "fieldName": "Title",      // Field to search in
#   "filterName": "technology", // Query parameter name
#   "isMandatory": true        // Required parameter
# }
# Then use: ?technology=searchterm

# REAL-WORLD EXAMPLE:
# Collection: BlogPosts
# Content Type: Blog (with fields: Title, Content, Comments, Likes)
# Filters:
# - fieldName: "Title", filterName: "technology", isMandatory: true
# - fieldName: "Content", filterName: "content", isMandatory: false
# - fieldName: "Comments", filterName: "comments", isMandatory: false
#
# Usage:
# ?technology=test                    // Search Title containing "test"
# ?technology=test&content=guide      // Search Title containing "test" AND Content containing "guide"
# ?technology=hello&comments=good     // Search Title containing "hello" AND Comments containing "good"
